# 과정 인식형 컴퓨팅 사고 평가 설계

이 문서는 v0.6에서 코드가 실제로 구현하고 있는 평가 설계를 정리합니다.
화면 문구와 채점 로직이 이 문서와 어긋나면 문서가 아니라 코드를 기준으로 봅니다.

---

## 1. 평가 축

평가 축은 컴퓨팅 사고 6요소입니다. 코드에서는 `CtElement`가 이 여섯 값만 가집니다.

| 축 | 코드 값 | 주로 붙는 과정 증거 |
| --- | --- | --- |
| 추상화 | `abstraction` | 핵심 조건 선택 |
| 문제 분해 | `decomposition` | 네트워크 조작, 하위 문제 분리 |
| 알고리즘적 사고 | `algorithm` | 해결 순서 배열, 경로 그리기, 상태 추적 |
| 평가·디버깅 | `evaluation` | 오류 찾기, 판단 근거 점검 |
| 패턴 인식 | `pattern` | 패턴 표시 |
| 일반화·전이 | `generalization` | 전이 문제, 규칙 일반화 문항 |

### DOK는 평가 축이 아닙니다

DOK는 `Problem.dokLevel`이라는 **선택 항목**으로만 존재합니다.

- 문항의 인지적 요구 수준을 검토할 때 참고하는 태그입니다.
- 점수 계산에 전혀 들어가지 않습니다. `buildCtProfile`, `responseScore`, CSV 점수 열 어디에도 쓰이지 않습니다.
- 비워 두어도 됩니다. 타당성 검토에서 "정보" 수준의 안내만 나옵니다.

### AI 활용 역량은 따로 봅니다

AI 도움 기록은 `Attempt.tutorUses`에 남고 `buildAiUsage`로만 요약합니다.

- 컴퓨팅 사고 점수에 더해지지도, 깎이지도 않습니다.
- 학생 결과 화면과 교사 대시보드에서 별도 영역으로 표시합니다.
- CSV에서도 `AI도움총사용`, `AI힌트`, `AI반례`, `AI디버깅`, `AI최대힌트단계`,
  `AI없이푼문제수` 열로 분리되어 나갑니다.

## 2. 평가 흐름

한 문제마다 다음 다섯 단계를 거칩니다. 단계 사이의 기록은 서로 덮어쓰지 않습니다.

| 단계 | 화면 | AI 도움 | 남는 기록 |
| --- | --- | --- | --- |
| 1. 독립 풀이 | 첫 답 + 확신도 | **사용 불가** | `initialAnswer`, `confidence` |
| 2. 과정 증거 | 문제 유형별 조작 | 사용 가능 | `processResponses` |
| 3. 최종 판단 | 최종 답 + 수정 이유 | 사용 가능 | `finalAnswer`, `revisionReason` |
| 4. 독립 전이 | 구조가 같은 새 문제 | **사용 불가** | `transferAnswer` |
| 5. 결과 확인 | 프로파일 | — | 위 전부 |

1단계와 4단계에서 AI 패널은 화면에 렌더링되지 않습니다(`StudentRunner`의 `tutorVisible`).

## 3. 문제 유형별 과정 증거

모든 문제에 같은 서술형 질문을 붙이지 않습니다. 문제 유형마다 다른 증거를 모읍니다.

| 문제 유형 | 과정 증거 유형 | 코드 값 | 학생이 하는 일 | 채점 |
| --- | --- | --- | --- | --- |
| 조건·규칙 | 핵심 조건 선택 | `multi_select` | 필요한 정보만 고르기 | 맞은 개수 − 틀린 개수 |
| 절차 | 해결 순서 배열 | `step_order` | 순서 바꾸기 | 자리마다 1점 |
| 경로 | 경로 그리기 | `path_draw` | 격자에 경로 그리기 | 항목 4개 |
| 상태 변화 | 상태 추적 | `state_trace` | 단계별 중간 상태 고르기 | 단계마다 1점 |
| 패턴 | 패턴 표시 | `pattern_mark` | 반복 단위 감싸기 | 항목 3개 |
| 네트워크 | 네트워크 조작 | `network_select` | 핵심 지점·연결 누르기 | 맞은 개수 − 틀린 개수 |
| 디버깅 | 오류 찾기 | `error_spot` | 잘못된 설명 바로잡기 | 정답 1개 |

### 경로 그리기 채점 (4점)

정답 경로와의 글자 단위 비교가 아니라 **경로의 성질**을 봅니다.
같은 길이의 다른 최단 경로도 정답으로 인정합니다.

1. 출발점에서 시작해 도착점에서 끝남
2. 한 칸씩 이어진 경로임 (같은 칸을 다시 지나지 않음)
3. 막힌 칸을 지나지 않음
4. 이동 횟수가 최소임

최소 이동 횟수는 격자에서 너비 우선 탐색으로 직접 계산합니다(`shortestMoves`).
교사가 적어 둔 값과 실제 계산이 다르면 타당성 검토가 경고합니다.

### 패턴 표시 채점 (3점)

시작 위치가 아니라 **가장 작은 반복 단위를 잡았는가**를 봅니다.
같은 주기의 다른 시작 위치도 정답입니다.

1. 이어진 한 덩어리를 표시함
2. 표시한 단위가 전체 무늬를 채움
3. 가장 작은 반복 단위임

### 정답이 그대로 보이지 않게 하는 장치

- 선택형 보기 순서는 학생마다 다르게 섞입니다(`shuffleAwayFromAnswer`, 학생 키로 고정된 난수).
- 순서 배열 문항의 초기 순서도 섞습니다. 교사가 입력한 순서가 곧 정답이 되지 않습니다.
- 섞은 결과가 우연히 정답과 같아지면 한 칸 밀어 냅니다.
- 교사가 저장한 보기 순서가 정답 순서와 같으면 타당성 검토가 "반드시 고칠 항목"으로 표시합니다.

## 4. 해석 지표

정답률만으로는 추측 해결과 전략적 해결을 구분할 수 없습니다.
v0.6은 다음 네 가지를 함께 보여 줍니다.

### 결과 × 과정 사분면 (`buildQuadrant`)

과정 수행률 60%를 기준선으로 씁니다.

| | 과정 증거 충분 | 과정 증거 약함 |
| --- | --- | --- |
| **최종 정답** | 전략적 해결 | **추측 의심** |
| **최종 오답** | 실수 가능 | 개념 보완 필요 |

### 확신도 보정 (`buildCalibration`)

- **과신**: "확실함"이라고 했지만 첫 답이 틀림
- **과소 확신**: "잘 모르겠음"이라고 했지만 첫 답이 맞음
- "조금 확실함"은 셈에서 제외합니다.

### 수정의 질 (`buildRevisionQuality`)

- 오답 → 정답: 과정 확인이 실제로 도움이 되었습니다.
- 정답 → 오답: 과정 문항이 학생을 잘못된 방향으로 흔들었을 수 있습니다. 문항을 검토하세요.
- 정답 유지 / 오답 유지

### AI 활용 (`buildAiUsage`)

도움 없이 푼 문제 수, 도움을 쓴 문제 수, 가장 깊은 힌트 단계,
도움을 받은 뒤 답을 고친 문제 수, 종류별 사용 횟수를 봅니다.
점수와 섞지 않으므로 "도움을 잘 쓰는 학생"과 "많이 맞힌 학생"을 따로 볼 수 있습니다.

## 5. 정답을 주지 않는 도움

`src/services/tutor.ts`는 외부 모델을 부르지 않습니다. 문제 자체에서 질문을 만듭니다.

| 종류 | 하는 일 |
| --- | --- |
| 생각 힌트 | 단계가 올라갈수록 구체적인 질문. 교사가 적은 힌트가 있으면 그것을 먼저 씁니다 |
| 반례 질문 | 학생이 지금 고른 답을 가정하고, 그 가정이 무너지는 지점을 찾게 합니다 |
| 디버깅 점검 | 학생이 남긴 과정 기록을 근거로 스스로 점검할 지점을 알려 줍니다 |

지켜지는 규칙:

- 정답 선택지의 문장이나 정답 문자를 말하지 않습니다.
- 맞았는지 틀렸는지 판정해 주지 않습니다.
- **문제에 이미 적혀 있는 규칙 위반만** 알려 줍니다.
  (예: "지금 경로는 지나갈 수 없는 칸을 통과합니다" — 이는 문제의 규칙이지 정답이 아닙니다)
- 아직 학생이 만나지 않은 과정 문항은 언급하지 않습니다.
- 모든 도움말은 `leaksAnswer` 검사를 통과해야 화면에 나갑니다.
  통과하지 못하면 안전한 일반 문장으로 바뀝니다.
- 교사가 적은 힌트가 정답을 노출하면 **문제를 저장할 수 없습니다**.

`npm run check:content` 는 자동 생성 힌트 1~4단계와 교사 힌트 전부를
모든 문제에 대해 검사합니다.

## 6. 타당성 검토가 잡아내는 것

교사 화면의 **타당성 검토** 탭과 문제 제작기 상단에서 같은 검사가 돌아갑니다.

| 수준 | 뜻 | 예 |
| --- | --- | --- |
| 반드시 고칠 항목 | 평가가 성립하지 않음 | 보기 순서가 정답 순서와 같음, 힌트가 정답 노출, 도착 불가 격자, 전이 문제가 본문제와 동일 |
| 확인 권장 | 해석이 흐려짐 | 측정한다고 표시했지만 증거가 없는 요소, 최소 이동 횟수 표기 불일치, 전이 선택지가 본문제와 동일 |
| 정보 | 참고 | DOK 태그 없음, 과정 유형이 한 가지뿐 |

점수는 100점에서 시작해 반드시 고칠 항목마다 25점, 확인 권장마다 10점을 뺍니다.

학급 수준에서는 **사고 요소 커버리지**를 함께 봅니다.
어떤 축의 문항 수가 0이면 그 축의 프로파일은 해석할 수 없으므로
학생 화면과 대시보드 모두 백분율 대신 "측정 없음"이라고 적습니다.

## 7. 데이터가 남는 위치

| 무엇 | 어디 |
| --- | --- |
| 교사가 만든 문제 | 브라우저 `localStorage` |
| 학생 풀이 기록 | 브라우저 `localStorage` + (서버 모드) `public.server_attempts` |
| 게시한 과제 스냅샷 | `public.published_sets.problem_snapshots` |
| AI 도움 기록 | 학생 기록 안의 `tutorUses` |

새 과정 증거 유형을 추가해도 학생의 답은 항상 `selections: string[]` 한 가지 모양으로 저장됩니다.
그래서 데이터베이스 스키마를 바꾸지 않고도 문항 유형을 늘릴 수 있습니다.

| 유형 | `selections`에 들어가는 값 |
| --- | --- |
| `path_draw` | 지나간 칸 좌표 `"3,4"` 순서대로 |
| `state_trace` | 단계 순서대로 고른 보기 id |
| `pattern_mark` | 표시한 토큰의 인덱스 `"0"`, `"1"` … |
| `network_select` | 고른 노드 id 또는 간선 id `"C-D"` |
