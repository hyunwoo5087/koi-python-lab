# 비버 사고과정 온라인 저지 v0.6.0

비버형 문제의 **첫 답 → 과정 증거 → 최종 판단 → 독립 전이**를 분리해 기록하는
Vite + React + TypeScript 프로젝트입니다.

정답 여부만 확인하는 기존 방식의 한계를 보완해, 학생이 문제를 해결하는 과정에서 드러나는
컴퓨팅 사고를 평가합니다. Supabase를 연결하지 않으면 브라우저 `localStorage`만으로 동작하고,
연결하면 학생들이 여러 컴퓨터에서 과제 코드로 접속해 결과를 서버에 저장할 수 있습니다.

평가 설계의 근거와 채점 방식은 [PROCESS_ASSESSMENT_KO.md](PROCESS_ASSESSMENT_KO.md)에 정리했습니다.

---

## 빠른 실행

Node.js 20.19 이상 또는 22.12 이상이 필요합니다.

```
npm install
npm run dev
```

브라우저에서 터미널에 표시된 주소(기본값 `http://localhost:5173`)를 엽니다.
Supabase 없이도 학생 풀이와 교사 문제 제작이 모두 동작합니다.

## Supabase 연결 (여러 컴퓨터에서 쓰려면)

### 방법 1 — 명령 한 줄 (권장)

```
npm run setup:supabase
```

Project Ref와 Publishable key를 물어보고 `.env.local`을 만들고,
`supabase/schema.sql`을 클립보드에 복사한 뒤 SQL Editor를 열고, 연결까지 확인합니다.
Windows·macOS·Linux에서 같은 방식으로 동작하며 PowerShell과 Supabase CLI를 쓰지 않습니다.

Windows에서 `setup-supabase-easy.cmd`를 두 번 눌러도 같은 스크립트가 실행됩니다.

### 방법 2 — 손으로 하기

배치 파일이 열리지 않거나 정책으로 막혀 있으면
[MANUAL_SETUP_KO.md](MANUAL_SETUP_KO.md)의 순서를 따르세요.
`.env.local` 두 줄을 직접 만들고 `schema.sql`을 붙여 넣는 방법을 화면 그림 없이 설명합니다.

### 연결 확인

```
npm run verify:supabase
```

앱 안에서는 **교사 대시보드 → 서버 배포** 화면 아래 **연결 진단**이
환경 변수부터 RLS까지 8단계를 점검하고, 막힌 단계마다 다음에 할 일을 알려 줍니다.

> 브라우저에는 **Publishable key만** 사용합니다.
> Secret key와 `service_role` 키는 절대 넣지 않습니다. 넣으면 진단이 즉시 경고합니다.
> `.env.local`을 고친 뒤에는 개발 서버를 껐다가 다시 켜야 값이 반영됩니다.

## v0.6 주요 변경

### 설정이 실제로 되게 만들기

- **배치 파일이 열리지 않던 원인을 고쳤습니다.**
  v0.5.1의 `.cmd` 파일은 줄바꿈이 LF였고 본문에 한글이 섞여 있어
  CMD가 `goto` 라벨을 제대로 읽지 못했습니다. 이제 배치 파일은 CRLF·ASCII로만 쓰고,
  실제 작업은 Node.js 스크립트가 합니다. `.gitattributes`로 줄바꿈을 고정했습니다.
- `curl --fail-with-body`(curl 7.76 이상 필요)를 쓰지 않습니다.
  Windows 10에 들어 있는 예전 curl에서도 확인이 됩니다.
- `verify-supabase.cmd`가 실패를 성공으로 보고하던 문제를 고쳤습니다.
  (`echo`가 `ERRORLEVEL`을 지우고 있었습니다.)
- Project Ref 자리에 대시보드 주소를 그대로 붙여 넣어도 알아서 인식합니다.
- 앱 안에 **연결 진단** 화면을 넣어 어디까지 되었는지 눈으로 확인합니다.
- 게시 성공 안내가 곧바로 사라지던 문제를 고쳤습니다.

### 평가 설계

- 평가 축을 **컴퓨팅 사고 6요소**로 맞췄습니다. **패턴 인식**을 추가했습니다.
- **DOK는 평가 축에서 제외**했습니다. `dokLevel` 보조 태그로만 남고 점수에 반영되지 않습니다.
- **AI 활용 역량을 컴퓨팅 사고 점수와 분리**해 별도 프로파일로 봅니다.

### 새 과정평가 문항 제작기

문제 유형마다 다른 증거를 모읍니다. 네 가지 조작형 문항을 새로 만들었습니다.

| 새 유형 | 학생이 하는 일 | 채점 |
| --- | --- | --- |
| 경로 그리기 | 격자에 직접 경로를 그림 | 연결성·장애물·최단성 4항목 |
| 상태 추적 | 단계별 중간 상태를 고름 | 단계마다 1점 |
| 패턴 표시 | 반복 단위를 감쌈 | 덩어리·타일링·최소성 3항목 |
| 네트워크 조작 | 핵심 지점·연결을 누름 | 맞은 수 − 틀린 수 |

교사 제작기에서 격자를 칠하고, 단계를 넣고, 무늬를 적고,
네트워크를 그려 정답을 화면에서 직접 누르며 만들 수 있습니다.

### 정답을 주지 않는 AI 도움

- **생각 힌트**(단계별), **반례 질문**(학생이 고른 답을 흔들기), **디버깅 점검**(과정 기록 기반)
- 최초 답 제출과 전이 문제 단계에서는 사용할 수 없습니다.
- 정답 문장·정답 문자 노출을 자동으로 검사하고, 새면 안전한 문장으로 바꿉니다.
- 교사가 적은 힌트가 정답을 노출하면 문제를 저장할 수 없습니다.
- 외부 모델이나 API 키가 필요 없습니다. 문제 자체에서 질문을 만듭니다.

### 문제 일괄 등록·내보내기

- JSON 파일 업로드 또는 붙여넣기로 여러 문제를 한 번에 등록합니다.
- 문제마다 검사해 형식이 어긋난 것은 건너뛰고 이유를 알려 줍니다.
- 전체 문제 또는 직접 만든 문제만 내려받아 오프라인에서 편집한 뒤 되돌릴 수 있습니다.
- 새 유형을 하나씩 쓴 **예시 묶음 4문제**를 버튼 하나로 불러올 수 있습니다.

### 타당성 검토

- 문제 유형에 맞는 증거인지, 정답이 새지 않는지, 표시한 사고 요소를 실제로 측정하는지 검사합니다.
- 순서 배열 문항의 보기 순서가 정답 순서와 같으면 반드시 고칠 항목으로 표시합니다.
- 학급 수준에서 사고 요소 커버리지와 과정 유형 분포를 봅니다.

### 프로파일 개선

- 6축 프로파일. 측정하지 않은 축은 0%가 아니라 **"측정 없음"** 으로 표시합니다.
- **결과 × 과정 사분면**으로 추측 해결과 전략적 해결을 구분합니다.
- **확신도 보정**(과신·과소 확신), **수정의 질**(오답→정답, 정답→오답)
- CSV를 학생별·문제별 두 가지로 내보냅니다. 과정 증거의 항목별 판정까지 담깁니다.

### 학생마다 다른 보기 순서

- 선택형 보기와 순서 배열 초기 순서를 학생마다 다르게 섞습니다.
- 교사가 입력한 순서가 곧 정답이 되지 않습니다.

## 자체 검사

```
npm run lint:types      # 타입 검사
npm run check:content   # 문제 데이터 검사
npm run build           # 배포용 빌드
```

`check:content`는 모든 기본 문제와 예시 묶음에 대해 다음을 확인합니다.

- 격자가 실제로 풀리는지, 기준 경로가 정말 최단인지
- 패턴의 반복 단위 표기가 실제 주기와 맞는지
- 단계별 정답이 보기 안에 있는지, 네트워크 정답이 그래프 안에 있는지
- 정답을 그대로 넣으면 과정 증거가 만점이 되는지
- 교사 힌트와 자동 생성 힌트 1~4단계가 정답을 노출하지 않는지
- 타당성 검토의 "반드시 고칠 항목"이 하나도 없는지

## Supabase 구조

| 항목 | 내용 |
| --- | --- |
| 교사 인증 | 이메일·비밀번호 (Supabase Auth) |
| 교사별 과제 | `published_sets` (교사별 RLS) |
| 학생 제출 | `server_attempts` (교사는 자기 과제의 제출만 조회) |
| 학생 접근 | 테이블 직접 접근 차단, RPC만 허용 |
| 중복 제출 | 같은 제출 ID의 재시도는 갱신, 새 행을 만들지 않음 |
| 과제 코드 | 다른 교사가 쓰는 코드는 가져갈 수 없음 |
| 문제 스냅샷 | 게시 시점의 문제를 그대로 저장 |

`schema.sql`은 여러 번 실행해도 안전합니다.
이미 저장된 과제와 학생 제출 기록은 지워지지 않습니다.
새 버전으로 올릴 때도 그냥 다시 붙여 넣고 Run 하면 됩니다.
